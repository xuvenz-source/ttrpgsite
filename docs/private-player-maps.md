# Staged private split maps and chat
This migration is NOT applied. It must run after weapon/reference and multiple-character migrations, before frontend.
DM chooses an optional map override per campaign member. Without an override, the member follows the published party map. Access to battle map rows, map image storage, map tokens, token monitors, and map-scoped chat is authorized at the database layer. Chat has a before-insert trigger so RPC-produced weapon/spell/macro/dice messages cannot silently leak into party chat. DM can read all maps and all map chat; a player can only read their assigned/party map content. DM current view is stored for RPC chat routing.

QA/security prior to release: two player accounts assigned different maps; confirm each cannot select, list, access map image paths, subscribe to map tokens, or query chat from the other map; DM still sees both. Check private dice/spell/weapon/reference messages. Check reassignment to Party default and map deletion fallback.
